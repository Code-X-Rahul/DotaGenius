**SSE endpoint** (`src/app/api/jobs/[jobId]/status/route.ts`):
Implement exactly as shown in RESEARCH.md Pattern 2:
- `export const dynamic = 'force-dynamic'`
- GET handler creates a ReadableStream
- Use BullMQ `QueueEvents` to listen for 'progress' and 'completed' events for the specific jobId
- Stream SSE events: `data: {"stage":"downloading","percent":0}\n\n`
- On 'completed': send final event and close stream
- On 'failed': send error event and close stream
- Clean up QueueEvents on client disconnect (req.signal abort)
- Also check initial job state on connection -- if job already completed, send complete event immediately and close

**useJobStatus hook** (`src/hooks/useJobStatus.ts`):
- Client hook accepting jobId (string | null)
- Uses EventSource to connect to `/api/jobs/{jobId}/status`
- Returns `{ stage, percent, error, isComplete }`
- Handles EventSource onerror (reconnect handled by browser, but show error state after 3 failures)
- Cleans up EventSource on unmount
- If jobId is null, returns idle state

**StatusTimeline component** (`src/components/StatusTimeline.tsx`):
- Visual timeline/stepper showing pipeline stages:
  1. "Submitted" (checkmark when past)
  2. "Downloading Replay" (spinner when active, checkmark when past)
  3. "Parsing Replay" (spinner when active, checkmark when past)
  4. "Complete" (checkmark when done)
- Each step shows its status: pending (gray), active (blue with spinner), complete (green with checkmark), failed (red with X)
- Accepts `stage` and `percent` props
- If stage is 'failed': show error state with error message

**Status page** (`src/app/match/[matchId]/page.tsx`):
- Client component that reads matchId from params and jobId from searchParams
- First: GET `/api/matches/{matchId}` to check if match already exists

  - If complete: show "Re-analyze" button that POSTs to create new job
  - If in progress or new: show StatusTimeline with SSE updates
- Uses useJobStatus hook when there's an active jobId
- When job completes: refetch match data and show results
- Save to recent analyses (localStorage) when job completes

  - "Parse failed" for corrupted files
  - "Download failed" for CDN errors
  - Each error shows explanation and "Try a different match" link back to landing page
