**Prisma schema** (`prisma/schema.prisma`):
Define four models exactly as specified in 01-RESEARCH.md database schema section:
- `Match`: id (cuid), matchId (BigInt, unique), duration, startTime, gameMode, radiantWin, cluster, replayUrl (optional), demFilePath (optional), parsedAt (optional), status (default "pending"), errorMsg (optional), createdAt, updatedAt. Has relations to Player, CombatLogEvent, PositionSnapshot. Map to "matches".
- `Player`: id (cuid), matchId (BigInt), playerSlot, heroId, accountId (optional BigInt), kills, deaths, assists, goldPerMin, xpPerMin, lastHits, denies, heroDamage, towerDamage, heroHealing, items (Json). Unique on [matchId, playerSlot], indexed on matchId. Map to "players".
- `CombatLogEvent`: id (cuid), matchId (BigInt), gameTime, eventType, attackerHero (optional), targetHero (optional), inflictor (optional), value (optional Int), isAttackerHero (default false), isTargetHero (default false). Indexed on [matchId, gameTime] and [matchId, eventType]. Map to "combat_log_events".
- `PositionSnapshot`: id (cuid), matchId (BigInt), gameTime, heroId, x (Float), y (Float), gold, xp. Indexed on [matchId, gameTime] and [matchId, heroId]. Map to "position_snapshots".
- Use `postgresql` provider with `env("DATABASE_URL")`.

Run `npx prisma generate` to generate the client (do NOT run `prisma db push` yet -- that requires a running database).

**Prisma client singleton** (`src/lib/db.ts`):
Standard Next.js Prisma singleton pattern -- store client on globalThis in development to avoid too many connections during hot reload.

**Redis connection** (`src/lib/redis.ts`):
Create ioredis connection from `REDIS_URL` env var with `maxRetriesPerRequest: null` (required by BullMQ). Export as `redisConnection`.

**Validation** (`src/lib/validation.ts`):
- `matchIdSchema`: zod string schema, regex `/^\d{8,12}$/`, error message "Match ID must be 8-12 digits"
- `validateMatchId(input: string)`: returns `{ valid: boolean; error?: string }`

**Vitest config** (`vitest.config.ts`):
